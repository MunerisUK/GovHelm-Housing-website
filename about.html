About

Built for housing, priced to be adopted

IHAP began with a simple observation: every housing provider in the country solves the same problems, separately, and pays far more for the privilege than the work warrants.

What IHAP is

IHAP — the Integrated Housing Application Platform — is a commercial system for managing housing services end to end: the housing register, needs assessment, allocations and lettings, homelessness casework, tenancy management and the statutory returns that follow from all of it.

It is delivered as twelve modules over a shared core. You can run all of them, or run the register and allocations alongside systems you already have. The core is what makes the difference: one household record, one set of scheme rules, one audit trail, one permission model.

What IHAP is not

It is not free, and we do not pretend otherwise. IHAP is commercial software with a licence fee, set low deliberately. What it is not is tiered: there is no cut-down edition, no module held back for a premium bundle, and no per-seat count that grows every time you hire a caseworker.

It is also not a finance system, an asset management system or a contact centre. Those exist, most providers already run them, and IHAP's job is to connect to them cleanly rather than replace them.

Why it exists

Housing management software is a concentrated market. Contracts run for years, migration is expensive enough to be a deterrent in itself, and the cost of a change is set by the supplier rather than the difficulty of the work. Meanwhile the statutory landscape keeps moving: the Homelessness Reduction Act, the Social Housing (Regulation) Act, Awaab's Law, tenant satisfaction measures.

Each of those changes is implemented separately by every provider, paid for separately and tested separately. Building the common parts once, and charging modestly for them, is the obvious answer to work that everybody has to do.

How it is built

The platform is a set of services around a PostgreSQL data store, packaged as containers, with a documented REST API and an event stream. It runs on a single virtual machine for a small provider and on Kubernetes for a large one. The architecture page covers this properly.

Product direction is set by Muneris with the providers running the platform, through a customer advisory group that meets quarterly and sees the roadmap before it is published.

Design principles

Six commitments we hold the code to

One record for a household

If a person appears twice, something has gone wrong. Identity, relationships and address history are modelled once and shared by every module.

Configuration over code

Allocation schemes, bands, letters and workflows are data. Changing your scheme should not require a developer or a release.

The audit trail is a feature

Every decision records who, when, under which scheme version, and why. A decision you cannot explain is a decision you cannot defend.

Accessible or it is not finished

WCAG 2.2 AA is a merge requirement, not a later phase. The people most dependent on housing services are the least able to fight a bad interface.

Boring, documented technology

PostgreSQL, containers, REST, OpenAPI. A platform that outlives its original team has to be deployable by people who never met them.

Data belongs to the provider

Documented schema, standard formats, full exports included in the licence. Leaving should be as straightforward as arriving.

Who builds it

One team, accountable for the whole platform

IHAP is built and supported by Muneris. The same team writes the platform, runs the implementations and answers the support calls, which is deliberate: a supplier that has to live with its own decisions makes better ones.

Providers running IHAP sit on a customer advisory group that meets quarterly. It sees the roadmap before it is published, and the statutory items on it are shaped by the people who will have to work to them. It is not a user group with no influence; if every provider on it says a duty does not work the way we have modelled it, we change the model.

Implementation, data migration, hosting and support are available from Muneris. Nothing in the licence prevents you doing implementation work yourself or with a partner, and the configuration tooling is built on the assumption that you will.

Licensing

IHAP is licensed commercially, as an annual subscription covering the whole platform: every module, the API, the integration adapters, the migration tooling, updates and security patches.

The fee scales with the size of the provider rather than with seats, so putting more of your team on the system never costs more.
