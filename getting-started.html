Getting started

A full IHAP environment with sample data, running on your machine, in about ten minutes. Ask for evaluation credentials and the bundle is yours for 60 days.

  • Docker or Podman
  • 8 GB RAM
  • 60-day evaluation, no obligation

Prerequisites

  • Docker Engine 24+ with Compose v2, or Podman 4+ with podman-compose
  • 8 GB of RAM available to the container runtime, and 10 GB of disk
  • Evaluation credentials for the IHAP registry — request them here, usually issued the same day
  • Ports 8080, 8081 and 5432 free on the host

Everything else — PostgreSQL, object storage, the search index, the message broker and a mock identity provider — runs in the compose stack.

Install

Sign in to the registry with your evaluation credentials and start the stack. The first run pulls images and seeds the database, which is the slow part.

Terminal

docker login registry.ihap.dev            # evaluation credentials

curl -fsSLO https://get.ihap.dev/evaluation/compose.yaml
curl -fsSLO https://get.ihap.dev/evaluation/.env.example
cp .env.example .env

docker compose --profile demo up -d

# watch the seed job complete
docker compose logs -f ihap-seed

When the seed job finishes, two applications are available:

  • Citizen portal — http://localhost:8080
  • Staff workspace — http://localhost:8081

Sign in

The evaluation profile starts a mock identity provider with pre-seeded accounts. Passwords are demo for every account; the mock provider is never enabled outside the evaluation profile.

AccountRoleWhat to try
officer@demo.localAllocations officerAssess an application, set a band, run a shortlist
caseworker@demo.localHomelessness caseworkerOpen a prevention duty and build a Personalised Housing Plan
manager@demo.localService managerReview queues, timeliness dashboards and exception reports
admin@demo.localSystem administratorEdit the allocation scheme, roles and letter templates
applicant@demo.localResident (portal)Complete an application, upload evidence, place a bid

A suggested tour

  1. 1

    Apply as a resident

    Sign in to the portal as the applicant account and complete the housing application. Note that it saves as you go and that evidence uploads once.

  2. 2

    Assess as an officer

    In the staff workspace, pick the application off the assessment queue. The scheme rules are shown beside the evidence; set a band and record a reason.

  3. 3

    Run a lettings cycle

    Publish an advert, place bids from the portal, then close the cycle and run the shortlist. Compare the automatic order with the scheme rules.

  4. 4

    Open a homelessness case

    As the caseworker, open a prevention duty for the same household. The application data is already there; nothing is rekeyed.

  5. 5

    Look at the audit trail

    Open any decision and read its history: who, when, under which scheme version, and the stated reason.

Change something

The point of the demo is that it is configurable. Edit the scheme, apply it, and re-run the shortlist to see the difference.

Terminal

# edit the allocation scheme
$EDITOR config/scheme/demo-scheme.yaml

# validate before applying — this catches most mistakes
docker compose exec ihap-core ihapctl scheme validate config/scheme/demo-scheme.yaml

# apply as a new scheme version (existing decisions keep the old version)
docker compose exec ihap-core ihapctl scheme apply config/scheme/demo-scheme.yaml \
  --effective-from 2026-10-01

Call the API

The evaluation stack issues tokens from the mock provider. The specification is served by the running instance, so you can point any OpenAPI tool at it.

Terminal

# fetch a client-credentials token
TOKEN=$(curl -s http://localhost:8081/oauth/token \
  -d grant_type=client_credentials \
  -d client_id=demo -d client_secret=demo | jq -r .access_token)

# list open homelessness cases
curl -s "http://localhost:8081/api/v1/cases?type=homelessness&status=open" \
  -H "Authorization: Bearer $TOKEN" | jq '.data[] | {reference, duty, days_remaining}'

# the OpenAPI document
curl -s http://localhost:8081/openapi.json | jq '.info'

Evaluation data only

The evaluation profile seeds fictional households and properties, enables a mock identity provider and disables outbound email and SMS. It is not a production configuration and refuses to start with IHAP_ENV=production.

The evaluation licence runs for 60 days and carries no obligation. Production use needs a full licence.

Troubleshooting

If the seed job fails, it is almost always memory. Give the container runtime at least 8 GB and run docker compose down -v before retrying.

Port conflicts can be resolved by changing the port variables in .env.
