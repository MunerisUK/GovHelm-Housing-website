Frequently asked questions

The questions that come up in evaluation, procurement and governance boards, answered as plainly as we can manage.

The project

Is IHAP really free, or is this an open core model?

Really free. The repository contains the entire platform under the Apache License 2.0. There is no enterprise edition, no licence key, no per-seat count and no feature held back for a paid tier.

Suppliers, including the project's steward, may charge for hosting, implementation and support. None of that changes what is in the release.

Who is behind it?

The project is stewarded by Muneris, which contributes the core engineering team, and directed by a technical steering group that includes the organisations running the platform. See governance.

What happens if the maintainers lose interest?

You keep everything you have: the code, the data, the schema and an irrevocable licence. The governance model sets out succession, and in the worst case the platform is one you can maintain yourself or pay any supplier to maintain, because there is nothing proprietary in the stack.

That is a materially better position than the equivalent risk with a proprietary system, where the supplier ceasing trading is an emergency.

Is it production ready?

Not yet. IHAP is pre-release and working towards 1.0, which is the first release with a supported upgrade path and a stable API contract. The roadmap shows what is shipped and what is not.

Providers are running earlier versions in pilot and test environments. Going to production before 1.0 is possible but should be a deliberate decision taken with the community.

Procurement and cost

If the software is free, what does it actually cost?

Infrastructure, implementation, data migration, configuration, training and ongoing operations — the same costs any housing system carries, minus the licence and minus change control.

In our experience the licence is rarely the largest line. Where open source changes the economics most is in the second and third years: a scheme change or a new statutory return is work you can do, commission competitively, or take from another provider who has already done it.

Do we still need to run a procurement?

For the software itself, no: there is nothing to buy. For implementation, hosting or support you procure services in the normal way, and the absence of licensing usually makes that simpler and more competitive.

Can we get commercial support?

Yes, from Muneris and from any other supplier who chooses to offer it. The project does not certify or endorse suppliers, and no supplier gets privileged roadmap access.

What is the exit strategy?

Documented schema, open formats, full export tooling in the repository and no licence to terminate. You can also simply keep running the version you have indefinitely, which is not an option with a terminated proprietary contract.

Technical

Can it run alongside our existing systems?

Yes, and most implementations do. The integrations hub is designed for a long transition period where IHAP owns some services and incumbent systems own others. See integrations.

Does it have to be in the cloud?

No. IHAP runs on your own infrastructure, in your own cloud tenancy, or with a supplier. It does not phone home and has no dependency on any service the project operates.

What about multi-tenancy for shared services?

Supported through partner-scoped access, where several organisations share an instance and each sees its own stock plus the shared applicant pool. Full partnership support is a 1.2 item; see the roadmap.

How do we migrate five years of case notes?

With the migration tooling in the repository, and with realistic expectations. Structured data maps cleanly; free-text notes are loaded with their provenance rather than parsed into false precision. Profiling the source data early is the single best predictor of how the migration goes.

Does it support Welsh legislation?

Partly. The core model covers England and Wales, and Welsh-specific duty sequences are in progress. Scotland and Northern Ireland are not currently in scope for the core; a fork or a contributed extension would be welcome.

Governance and risk

Will our information governance team accept open source?

In our experience yes, once the question shifts from “is publishing the code risky?” to “can we verify the controls?”. The security page sets out the controls, the threat model and the argument in full, and your team can review the actual code rather than a datasheet.

Who is liable if something goes wrong?

The Apache License disclaims warranty, as every open source licence does. Liability sits where you place it: with your own organisation if you self-support, or with the supplier you contract for support, under that contract. This is the same question as with any system; the difference is that it is explicit.

How do we know a statutory change will be implemented?

Statutory changes affecting every provider are the project's highest priority and are visible on the roadmap. You also have a route no proprietary contract offers: if the timeline does not suit you, you can fund or write the change yourself and everyone benefits.

Can we influence the roadmap?

Yes. Providers running IHAP in production can request a technical steering group seat. Anyone can open an issue or a design note, and practitioner calls are open to all. See governance.

Question not answered?

Ask in the open and the answer helps the next person searching for it.
