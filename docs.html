Configuration is yours, and version controlled

All of the above is text, kept in your own repository and applied through your deployment pipeline. Scheme changes get the same review and rollback story as code, which matters when a banding rule is challenged.

It also means the changes providers make most often are not change requests. You do not raise a ticket to alter your own allocation scheme.

Common questions

Short answers, with links to the long ones

How long does an implementation take?

A register-first implementation typically runs six to nine months from kick-off to go-live, with data migration and scheme configuration taking most of that. A full platform replacement is usually phased across eighteen months.

The variable is rarely the software. It is data quality in the incumbent system and how long it takes to agree the scheme configuration with the service.

Can we run it alongside our existing housing system?

Yes, and most providers do during transition. The integrations hub keeps the party and property records aligned in both directions, and you cut over one service area at a time. See integrations.

What skills does a team need to run it?

Standard platform operations: containers, PostgreSQL, and whatever you already use for CI and monitoring. No proprietary technology and no certification. Configuration is done by the service with support, not by developers.

Is support included in the licence?

Platform updates, security patches and defect fixes are included. Named support with response targets, out-of-hours cover and managed hosting are separate options priced alongside the licence. See the FAQ.

How do we get help?

Start with the documentation, then the support desk for defects and how-to questions. Providers in implementation also have a named contact in the delivery team. See contact.
